This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

FlowSync is a team task-management app in progress. Two independent projects in one repo:

- `backend/` — API in AdonisJS 7 (TypeScript, ESM, SQLite via Lucid ORM)
- `frontend/` — React 19 + Vite, currently the unmodified Vite starter template (no app UI built yet)

Only auth (signup/login/logout/profile) exists so far. There is no tasks/projects domain yet — that's presumably what gets built next.

## Commands

### Backend (run from `backend/`)

```bash
npm install
cp .env.example .env
node ace generate:key       # populates APP_KEY in .env
node ace migration:run
npm run dev                 # serves with HMR on http://localhost:3333
npm run build                # node ace build
npm test                     # node ace test
npm run lint
npm run format                # prettier --write .
npm run typecheck             # tsc --noEmit
```

Run a single test file/suite with ace directly, e.g. `node ace test tests/functional/auth.spec.ts`.

### Frontend (run from `frontend/`, in a separate terminal — backend keeps running)

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # tsc -b && vite build
npm run lint      # oxlint
npm run preview
```

## Backend architecture

AdonisJS 7 app using the framework's IoC-style structure. Key things that aren't obvious from any single file:

- **Routes → controllers**: `start/routes.ts` registers routes against `controllers` imported from `#generated/controllers` (a Tuyau-generated registry), not direct file imports. All API routes are under `/api/v1`, split into an unauthenticated `auth` group (`signup`, `login`) and an authenticated `account` group (`profile`, `logout`) gated by `middleware.auth()` from `start/kernel.ts`.
- **Auth**: token-based (`@adonisjs/auth` access-tokens guard, config in `config/auth.ts`) is the default (`api`) guard used by the API; a session guard (`web`) also exists but isn't wired to any route yet. `AccessTokensController` issues/revokes tokens; `NewAccountController` handles signup; `ProfileController` returns the authenticated user.
- **Generated schema files, do not hand-edit**: `database/schema.ts` defines `UserSchema`/`AuthAccessTokenSchema` base model classes and is regenerated by `node ace migration:run` — it's marked "DO NOT EDIT manually" at the top. Hand-written model logic (e.g. `User.initials`, `withAuthFinder` mixin, `accessTokens` provider) lives in `app/models/user.ts`, which `compose()`s the generated schema class with behavior mixins. `database/schema_rules.ts` controls schema-generation rules (currently empty) if generation needs tuning.
- **Import aliases**: subsystems are addressed via Node subpath imports defined in `backend/package.json` (`#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, `#middleware/*`, `#database/*`, `#generated/*`, etc.) rather than relative paths — use these when adding new files.
- **Response shape**: controllers call `serialize(...)` (added to `HttpContext` by `providers/api_provider.ts`) instead of returning raw objects, so every API response is wrapped as `{ data: ... }` consistently, including paginated Lucid results.
- **Transformers**: output shaping goes through `BaseTransformer` subclasses (e.g. `app/transformers/user_transformer.ts`), which whitelist fields via `pick()` — this is where you control what a model exposes over the API, separate from Lucid's own `serializeAs` column options.
- **Validation**: request validation uses VineJS validators in `app/validators/`, invoked via `request.validateUsing(...)` inside controllers (see `app/validators/user.ts` for shared `email()`/`password()` rule builders).
- **Middleware stack**: global middleware (JSON forcing, container bindings, CORS) is registered in `start/kernel.ts` for all requests; router middleware (bodyparser, session, shield, auth initialization, silent auth) applies to routed requests; `auth` is the only named middleware, applied explicitly per route group.

## Frontend architecture

Vanilla Vite + React 19 + TypeScript starter, unmodified from scaffold — no routing, state management, or API client set up yet. `oxlint` (not eslint) is the configured linter (`.oxlintrc.json`).

## Reglas de proceso
- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca commitear directo en `main`/`s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él, antes de darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo con la URL del PR.
